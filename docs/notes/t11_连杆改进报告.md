## 0. 一句话结论

1. **最省事的一组改动**（只动 3 根杆，都是"缩短"）：

   | 杆 | 现在 | 改成 |
   |---|---|---|
   | `link2.y` 大臂 | 290 | **235** |
   | `link3.x` 横偏 | 85.5 | **45** |
   | `gripper.z` 工具段 | 211 | **150** |

   **杆长之和 1064 → 908 mm（−15%）**，5 套互相独立的位姿集（每套 96 位姿 × 12 起点 × 400 迭代）复核：

   | 指标 | 基准臂 | 推荐方案 | |
   |---|---|---|---|
   | 严格合格率 | **9%** | **20%** | 位置<3mm ∧ 姿态<3° ∧ 最紧关节裕度>5° |
   | 分数（裕度/15° 的均值×100） | **8.0** | **17.7** | 逐套 5 次全部变好（×1.8~×5.1） |
   | IK 未解出 | 9% | 7% | |
   | 最大伸展 | 985 mm | 865 mm | **代价 −12%** |
   | 可达体素（50mm，30k 采样） | 13332 | 10677 | **代价 −20%** |
   | 三级任务域位置可达率 | 100% | 100% | 没变差 |

2. **收益的实质**：基准臂现在的"可解"有相当一部分是**把 joint1 / joint4 顶死在限位上凑出来的**
   （逐位姿最紧关节裕度中位数 = **0.0°**，一半位姿有 ≤5° 的关节）。改杆不是让它"够得着"，
   而是让**同样的限位**下解落在关节空间内部 —— 这才是实机上能动、能留余量的差别。

3. **连杆改不出"绕 Q 轴自转"**（三级 R4 的判决性问题）：
   绕插入轴能连续转过的弧，中位只有 **30°**，只有 **13%** 的位姿够 90°，还有 25% 的位姿一个角度都解不出来。
   这是**轴系拓扑**决定的、不是长度决定的。臂的 6 个关节是：
   「竖直 yaw ×2（`base_joint`、`joint3`）+ 互相平行的 pitch ×3（`joint1/2/4`，轴都沿 base X）
   + 绕**工具轴**的自转 ×1（`joint5`）」—— **没有"绕插入轴"那一级**
   （插入轴 = 夹爪 y，工具轴 = 夹爪 z，两者互相垂直，`joint5` 转的是后者）。
   ⇒ **加长/缩短任何一根杆都不解决**，要做三级得补一级腕部 roll（绕插入轴）。见第 6 节。

4. 想要更大的杠杆，**不在连杆上**：安装 yaw 扫描 / 装配臂位置是 README 里已经量过的更有效的两个旋钮
   （`armBuilder.html` 顶栏就能改），它与连杆改动**正交**，可以叠加。

## 1. 为什么又开一个评估文件

`armBuilder.html` 的数据面板里有一行「IK 复核 · 可解」，基准臂一直显示 ~100%。
但那个判据很宽：`位置<3mm 且 姿态<0.2rad(11.5°)`，而且**关节顶在限位上也算 ok**。
用它来比较"连杆怎么改"会得到"怎么改都是 100%"的假象。

`armLink.html` 换一套严格判据（面板里可调，默认值如下）：

| 项 | 面板原来那行 | armLink 的严格判据 |
|---|---|---|
| 位置误差 | < 3 mm | < 3 mm（不变） |
| 姿态误差（夹爪 y 与 −e⃗ 的夹角） | < 11.5° | **< 3°** |
| 关节限位裕度（解离最近限位多少度） | 不查 | **> 5°**，且按 15° 打满分 |
| 单点得分 | 0/1 | `找到严格解 ? clamp(裕度/15°,0,1) : 0` |
| 总分 | 可解率 | 各位姿得分的平均 × 100 |

同一批位姿、同一套解算器下，两套判据可以同时成立（自检里当场验证）：

```
严格判据：合格率 0~6%，未解出 10~25%
面板判据（位置<3mm 且 姿态<11.5°）：可解率 100%
```

## 2. 工具怎么用（`armLink.html`）

打开方式与 `armBuilder.html` 完全一样（双击、离线、零依赖）。
顶栏多一个 **⛓ 连杆调参** 按钮，右栏弹出一个面板（和「▦ 底盘 / 尺寸」同一套交互）：

| 区块 | 内容 |
|---|---|
| 1 · 目标与预算 | 位姿数 8/12/24/48、每起点预算 2/4/6/10、IK 迭代、位置/姿态容差、裕度门槛与满分、**杆长之和上限**（默认=基准 1064.1）、随机种子 |
| 2 · 旋钮 | 自动列出**除第 1 段（臂安装位）外**每段的 x/y/z 三个分量，共 18 个；默认只勾 6 个非零分量。每个旋钮可改上下界、可单独 ⟲ 扫描 |
| 3 · 跑 | 📈 灵敏度扫描（每根杆 K 档）· 🔍 全局搜索（随机重启 + 坐标下降）· ⏹ 停止 · ✅ 复核 · ↩ 恢复原始臂 · 📤 导出候选 JSON |
| 4 · 对比 | 基准（虚线）vs 当前（橙）的骨架 YZ 投影 + 逐段杆长增减 |
| 5 · 结果 | 每行一个方案：分数 / 合格率 / 裕度中位 / 姿态中位 / 未解出 / 杆长和 / 相对基准的改动。**点一行 = 应用 + 存入浏览器本地存档**（三维视图立刻变），「↩ 恢复原始臂」回到**打开面板时**那一份 |

> ★ **防"把候选当成原臂"**：面板顶部与数据面板都有一行
> 「当前模型 = 同济示例模型（原版，一字未改）」，一旦和原脚本 `demoModel()` 有差异就变成
> 「⚠ 当前模型 ≠ 同济示例模型（N 处不同）：link3.x 85.5→45 · …」。
> 注意两点：① 点结果行会**进本地存档**，下次打开直接是改过的模型（不再弹开始窗口）；
> ② 「恢复原始臂」恢复的是**打开面板时**的快照 —— 那时候模型已经被改过的话，救不回来，
> 只能用顶栏 **示例** 重新载入原版（会覆盖存档）。

- 全程**只写 `MODEL.links[i].pos[*]`**（= 各段 offset），`limits` 一个字节都不碰；
  每次评估前后都比对限位签名，变了会红字报警。
- 判据、位姿集、随机种子都可复现：同一个种子 + 同一套预算 → 逐位姿完全一样（自检里有断言）。
- 位姿集是**分层采样**（Halton），且"位姿数 12 是 24 的前缀"——调大位姿数只加新位姿、不改老位姿。

### 5.5 追问：把 `link4` 那 30mm 侧偏「弄直」会不会更好？（不会）

`link4` 的 offset 是 `(0, −30, 401.47)`，问"改成 `(0, 0, 402.59)`（保杆长）会不会更好"。
5 套独立位姿集 × 96 位姿 × 12 起点 × 400 迭代（`t11_link4_ab.json`）：

| 方案 | 分数（逐套） | 平均 | 合格率 | 杆长和 |
|---|---|---|---|---|
| 基准 `(0,−30,401.47)` | 7.1 / 3.7 / 7.8 / 12.4 / 9.0 | **8.0** | 9% | 1064.1 |
| 弄直 `(0,0,402.59)` | 7.0 / 4.3 / 8.4 / 6.0 / 10.0 | **7.1** | 8% | 1064.1 |
| 更斜 `y=−60`（3 套对照） | 5.1 / 7.2 / 5.8 | 6.0 | 7% | 1067 |
| 只去一半 `y=−15`（3 套对照） | 11.1 / 4.8 / 6.9 | 7.6 | 8% | 1063 |

**差别在噪声里**：−0.9 分；而**同一套方案在不同位姿集上的分数本来就摆动 ±3~6 分**
（基准自己 7.1 → 12.4）。几何上也几乎不动：杆长和 1064.1 不变、最大伸展 979 → 978、
可达体素 13332 → 13313（−0.1%）、末端高度范围一样。

> 那 30mm 是什么：`joint3`（竖直 yaw）的轴过 `link3` 原点，`link4` 原点到这条轴的**垂距**
> 就是 `|(0,−30)| = 30mm`；弄直之后 `joint3` 与 `joint4` 两条轴线会相交（那 30mm 的错位没了）。
> 但 30mm 放在 1064mm 的臂上太小，量不出差别。

> ★ 术语先澄清一下，免得读串：
> - **`link4` 才是"折"的那根** —— `(0,−30,401.47)` 有两个分量，`joint3`（竖直）与 `joint4`（水平）
>   两条轴线因此**错开 30mm、不相交**；"弄直"= 去掉这 30mm 的错位。
> - **`link3` 的 `(85.5,0,0)` 本身没有折角** —— 它是沿 `joint2` 轴的**纯平移错位**（side offset）。
>   所以对它说"弄直"其实是"**把这段错位缩短**"（上一版报告用"弄直"这个词不准确）。

**该动的是 `link3.x = 85.5`**（`joint2` 轴向上的纯平移错位，量级是那 30mm 的 3 倍，
`t11_lat.json` / `t11_lat.log`）：

| 方案 | 分数（5 套平均） | 合格率 | 杆长和 |
|---|---|---|---|
| 基准 85.5 | 8.0 | 9% | 1064 |
| `link3.x` **错位缩到 0** | **12.0** | 13% | 979 |
| `link3.x → 45` | **13.1** | 16% | 1024 |
| `link3.x→45` **且** `link4` 也弄直 | 8.6 | 10% | 1024 |

两条：① **要动的是 85.5 那根（缩短错位），不是 30 那根**（+50% ~ +64%）；
② **两处一起改反而互相打架**（13.1 → 8.6，5 套里 5 套都变差）——
错位之间有耦合，不能按"每个都越小越好"逐个拍。

对应模型（直接拖进工具看）：`示例臂_link4弄直.json`、`示例臂_横偏45.json`。

## 6. 绕 Q 轴自转：连杆改不出来（`t11_roll_probe.js`）

三级难度要求"以 Q 轴为旋转轴、在 90° 范围内以 5° 精准度旋转"。
如果读法是 **H1：Q ∥ e⃗（绕插入轴自转）**，那臂必须能在"位置 + 两轴姿态"都锁死的情况下
连续改变自转角。把它当 6 约束 / 6 关节的位姿 IK 实测（24 位姿 × [−90°,+90°) 每 15° 一个点）：

| 量 | 结果 |
|---|---|
| 位姿内能**连续**转过的最大弧 | 中位 **30°**，最大 135° |
| 够 90° 行程的位姿 | **13%** |
| 一个角度都解不出来的位姿 | 25% |
| 12 个角度全解的位姿 | 0% |

而且命中点**都聚在 roll ≈ 0** 附近（roll 的零点就是"夹爪 x 对齐核心 u 轴"，
也就是六方口该被夹的方向）——**插进去没问题，插进去以后转不动**。

这与 `06_报告\redo\阶段1b_结构约束与自转自由度.md` 的结构性结论一致：
4 个 pitch 轴共面平行 + 竖直 yaw ⇒ 自转角被锁死。**这是拓扑问题，不是长度问题**
（本报告第 5 节的所有方案都改不了它）。要做三级，得在腕部补一级**绕插入轴的 roll**。

## 7. 不建议动的 / 已知限制

1. **限位不要为了这个任务放宽**。README 第 5 节量过：把各关节限位整体放宽 ±25°，可解率只涨几个点
   —— 限位不是"够不着"的原因，而是"解贴边"的原因。本报告的做法是**保持限位不变**、用几何把解推进内部。
2. **安装 yaw / 装配臂位置**仍是更大的杠杆（README：安装朝向扫描是把可解率拉上去最有效的旋钮），
   但它和连杆改动**互不冲突**，两个都可以调 —— 本工具只负责把"连杆那一半"量清楚。
3. **"未解出"这一列不是几何不可达**：判据要求位置<3mm 且姿态<3°，数值 IK 在给定位姿预算内偶尔找不到，
   属于求解器运气（给 24 起点 × 600 迭代时 24/24 都能到 0.2° 级）。所以：
   - 分数适合**横向比较不同连杆**（大家用同一套位姿、同一套起点池），不适合当成绝对能力值；
   - 逐位姿的"最紧关节裕度"和"合格率"是更硬的读数。
4. 本工具**只做运动学**：没有碰撞、没有动力学、没有"腕部会不会撞到科技核心 / 底盘"。
   杆长一改，实体范围会变，真要落地得拿 `02_SW提取` 那套几何再过一遍。
5. 推荐方案把**最大伸展压掉 12%** —— 如果 2027 赛季还有"够远处"的任务，要自己权衡；
   本工具的面板第 4 区随时能看当前模型的最大伸展。
