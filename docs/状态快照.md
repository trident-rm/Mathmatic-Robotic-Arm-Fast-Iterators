## 0. 一句话现状

`armBuilder` 是一个**零依赖单文件网页工具**：给一套「杆 + 关节 + 坐标系 + 限位」，
算出带限位的可达集，并按比赛规则手册的三级位姿范围校核。
构型（臂型 / 规则 / 车体尺寸）与引擎已解耦，**加一条新臂或一套新规则不用改引擎**。

| | |
|---|---|
| 仓库 | `trident-rm/Mathmatic-Robotic-Arm-Fast-Iterators` |
| 分支 | `main`，与 origin 同步，工作区干净 |
| 交付物 | `build/armBuilder.html`（单文件、零依赖、双击即用；**已入库**） |
| 入口 | 打开后问 **新建 / 示例 / 上次** |
| 环境 | 浏览器零依赖；MATLAB 侧需 R2025b + Robotics System Toolbox（可选） |

## 1. 怎么验（评估用）

### 1.1 最快的一条路（不用装任何东西）

双击 `build/armBuilder.html` → 选 **示例** → 应看到同济示例臂（7 段链）+ 可达点云。
右侧四个可折叠面板：**模型链 / 旋转角度 / 装配参数 / 可达域·任务域数据**。

想试"新建"：点顶栏 **新建** → 走 5 步向导（单臂|双臂 → base_yaw 与基座位置 →
逐段搭 joint+link → 装配臂位置 → 夹爪插入轴）。

### 1.2 构建可复现（改源码后）

```bash
node web/build.js            # 在仓库根目录跑
node web/build.js --update-md5   # 有意改动产物时，显式更新基准并复核
```

构建会断言 `armBuilder.html` 的 md5 等于**写死的基准**。
不等就报错退出 —— 这是"没被改坏"的机械保证。

### 1.4 干净 clone 复现（评估建议做一次）


## 2. 数据链路（评估时看这条，比看代码快）

```
web/src/configs/*.js      构型配置：臂型(model/arms) + 规则(rules) + 车体(chassis)
        │  applyConfig(id)
        ▼
web/src/modules/04-config.js   引擎与构型之间的唯一接口
        │  填 MODEL / ARMS / RULES / MAP / CHASSIS / SIZER
        ▼
01-kinematics  正解 / 采样 / 体素      ├─ 02-task-rules  任务域校核 / IK / 动画
03-chassis-size 底盘与尺寸            ├─ 06-ui  面板/折叠/滑条/装配参数
                                      └─ 07-wizard  新建向导
        │  node web/build.js 合成
        ▼
build/armBuilder.html      单文件交付物（md5 有基准断言）
```

**关键约定**：
- `MODEL` = 第 0 条臂；`ARMS[a]` = 第 a 条臂；`CHAIN` 是各臂首尾相接的**扁平**数组；
  `Q` 同样是扁平关节向量 ⇒ `qLimits()` / 按关节序号的函数天然支持多臂。
- `RULES` / `MAP` 可以为 `null`（没有规则的构型）——下游都做了守卫。
- 模型 JSON 里 `vehicle = {asm, insertAxis, gripAxis}`（装配位置与夹爪轴，随 JSON 走）；
  多臂时每条臂另有 `arm.asm`（它自己的装配位）。

## 3. 哪些地方**别信**（评估要点，请优先看这些）

这一节是刻意写的。前面几轮里，下面这些都**曾经是错的**，现在有守卫或自检盯着，
但值得评估者重点复核：

1. **`taskToBase` 的 off 参数**
   `taskToBase(p)` 是"只吃一个参数"的转发壳；`off` 必须走 `MAP.toBase(p, off)`。
   搞错的话**两条臂会算出同一个坐标**（踩过）。
   现在多臂统一走 `taskToBaseArm(p, a)`。

2. **要不要手动补安装旋转**
   MATLAB 的 `buildChain` 把 `base.yaw` 当**根部固定变换**加进树；
   凡是"树的根已含朝向"的地方**都不能再手动转一次**。
   踩过：`armFeasData` 里多转一次 ⇒ `chainFK vs armFeasData` 差 677mm。

3. **单位**
   `inverseKinematics` 的目标位姿是**米**，内部量是**毫米**。
   踩过：`t7` 把 mm 当 m 喂进去 ⇒ 残差恰好是 1000 倍（390490 vs 390.5），
   而且**被另一个"差 90°"的解释掩盖了一整轮**。

4. **`demoModel()` 的语义**
   它现在 = "当前模型"（点「示例」时用来重置），**不是**"配置里那条原始臂"。
   要后者用 `configModel(id)`。
   踩过：连杆面板拿 `demoModel()` 当基准 ⇒ 差异恒为空，**防呆功能静默失效**。

5. **按值导出的变量**
   自检沙箱的 `__api` 里，会被重新赋值的变量（`RULES` / `MAP` / `CHASSIS`）
   **必须用 getter 导出**，否则 `applyConfig` 之后拿到的是过期快照。

6. **`analyzeTask` 的两个入口**
   `analyzeTaskArm(a)` **只算不写 DOM**；`analyzeTask()` 逐臂跑一遍再渲染。
   多臂时面板上有臂选择器。

7. **单臂数值没变**（回归过）
   按臂改造之后，同济示例的任务域可达率新口径 100% vs 老口径 98.90%，
   差 1.1 个百分点 = 同分布随机采样的正常波动。**结论未变**。

## 4. 已知边界（确实做不到的）

1. **没有碰撞、没有动力学、没有重力** —— 只回答"运动学上能不能到"。
   底盘碰撞箱只是显示；机械臂没有碰撞体，所以不给整机包围盒（骨架量出来是假数）。
2. **多臂不做干涉检查**，也**不做协同装配**（"两只手一起抓一个"）。
   双臂就是**单臂三轴检验各做一次**：每条臂按自己的装配位单独校核，互不联动。
3. **关节限位只支持区间**；月牙形耦合区域靠 `crescentMargin` / `crescentBounds` 表达。
4. **样本占比 ≠ 体积占比**；要精确体积请看体素数。
5. **`t7` 曾经报"RST 可解 0/200"是假的**（上面第 3 条的 mm/m + 基准系问题）。
   修好后是 **199/200 = 99.5%，位置误差中位 0.00 mm**，
   与 `t9_ik_truth.py` 的独立求解器（320/320）互相印证。

## 6. 还剩什么 / 建议下一步

**评估本身**：建议先做 §1.4 的干净 clone 复现，再按 §3 逐条复核那几个"曾经错过的地方"。

**功能上仍缺的**（都不是 bug，是没做）：

1. **没有固定的 UI 冒烟自检**。目前每次改 UI 都是我临时写无头探针，
   踩过三次"沙箱绿、浏览器红"。**建议做 `t15_smoke_ui.js`**：
   无头打开 → 走一遍向导 → 拖滑条 → 切配置 → 断言零 JS 错误。
2. **每个 joint 的坐标系三轴朝向**：向导里有，但模型链面板的编辑表单与它不完全对齐。
3. **`HISTORY.md` 已经 1272 行**，五个附录有内容重叠（配置层 / 多臂 / UI 改版）。
   可以合并压缩一次，但**要保留每个坑的"复现 + 修法"**，那是它的价值所在。
4. **`docs/notes/`** 里三份报告（t7 复盘 / t9 IK 诊断 / t11 连杆改进）内容仍准确，
   但引用的一些路径是改动前的写法，读的时候留意。
